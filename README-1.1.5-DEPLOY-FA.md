# راه‌اندازی نسخه 1.1.5

## ترتیب الزامی

- ابتدا از پایگاه داده D1 نسخه پشتیبان بگیرید.
- فایل `cloudflare-worker/migration-v1.1.5-accounts-private-keys.sql` را یک بار روی دیتابیس موجود اجرا کنید؛ دیتابیس را حذف یا از نو ایجاد نکنید.
- Worker را با فایل `cloudflare-worker/nexus-gamebooster-api.js` جایگزین کنید.
- پنل مدیریت را با `cloudflare-worker/admin-v1.0.html` جایگزین کنید.
- مقدار Secret با نام `ADMIN_TOKEN` و Binding با نام `DB` را بدون تغییر نگه دارید.
- اپ را با Android Studio یا Gradle روی سیستم دارای دسترسی به مخزن‌های Gradle بسازید.

## نکات

- شماره‌حساب با شناسه نصب ساخته می‌شود و در جدول `customer_accounts` نگهداری می‌شود.
- کلید خصوصی فقط روی همان شناسه نصب و شماره‌حساب مجاز می‌شود.
- کلید عمومی بین شماره‌حساب‌ها مشترک است و ظرفیت دستگاهی دارد.
- کلید تستی از نوع مستقل `test` است تا پیام انقضای مخصوص خودش را نشان دهد.
- آنلاین یعنی آخرین heartbeat در پنج دقیقه گذشته؛ برنامه در حالت فعال هر ۳۰ ثانیه sync می‌کند.
- متن کامل کلیدهای جدید در دیتابیس ذخیره می‌شود تا پنل بتواند آن‌ها را دوباره نمایش دهد. دسترسی پنل به این اطلاعات را محدود نگه دارید.
- این migration را دوباره اجرا نکنید؛ دستورات ALTER TABLE در صورت اجرای مجدد خطا می‌دهند.


## رفع خطای ساخت کلید در پنل ادمین (از نسخه 2.2.1)

برای کارکرد صحیح ساخت کلید، فایل `nexus-gamebooster-api.js` همین بسته باید روی همان Worker منتشر شود و Migration `migration-v1.1.5-accounts-private-keys.sql` باید دقیقاً یک‌بار روی دیتابیس D1 فعلی اجرا شده باشد. قبل از Migration از دیتابیس نسخه پشتیبان بگیرید. سپس پنل `admin-v1.0.html` همین بسته را باز کنید، آدرس Worker و مقدار Secret با نام `ADMIN_TOKEN` را وارد و متصل شوید. اگر خطای 401 دیدید، مقدار توکن پنل و Secret باید دقیقاً یکسان باشند. اگر خطای `no such column` یا خطای D1 دیدید، Migration اجرا نشده یا روی دیتابیس دیگری اجرا شده است. کلید خصوصی فقط برای شماره‌حسابی صادر می‌شود که قبلاً در همین API ثبت شده باشد؛ برای آزمایش ابتدا کلید عمومی یا تستی بسازید. برای بررسی ساختار دیتابیس بدون تغییر داده، `cloudflare-worker/verify-v2.2.1.sql` را اجرا کنید.
